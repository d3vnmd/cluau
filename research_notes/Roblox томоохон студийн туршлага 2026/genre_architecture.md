## Q1. How do successful games structure server vs client per genre? Entity counts and lag avoidance

### Takeaway
The 2026 baseline: the server owns all state that matters (currency, inventory, progress, damage, placement), and clients render, predict and interpolate. For competitive movement and combat, Roblox now ships an engine-level **Server Authority** model (client prediction plus rollback and resimulation, fully released in 2026). It replaces much of what Chickynoid did by hand. For high-entity genres like tower defense, the common pattern is to keep the server simulation in plain Lua tables and let each client build and move the models locally from server timestamps, and to treat tower targeting, not rendering, as the real bottleneck.

### Cited Findings

**Cross-genre baseline (official)**
- Roblox's Server Authority model makes the server the "single source of truth for the entire game state, and clients are only trusted to report their own inputs". It "prevents entire classes of cheating like flyhacks or speedhacks." Clients predict a few frames ahead and roll back and resimulate when they mispredict. Mispredictions are "a normal and expected part". — [Server authority model, Creator Hub](https://create.roblox.com/docs/projects/server-authority) (source read via [GitHub mirror](https://github.com/Roblox/creator-docs/blob/main/content/en-us/projects/server-authority/index.md))
- Server Authority setup requirements: `Workspace.AuthorityMode = Server`, which automatically sets the other five: NextGenerationReplication on, PlayerScriptsUseInputActionSystem on, SignalBehavior Deferred, UseFixedSimulation on, and StreamingEnabled on. Core logic must live in `RunService:BindToSimulation()` callbacks in a ModuleScript required by both client and server. Simulation state such as health, ammo and inventory goes in **attributes** written only inside bound functions. `time()` is synchronized between client and server in this mode. — [Server authority model](https://create.roblox.com/docs/projects/server-authority)
- Server Authority limitations: Tools are "not fully supported yet", since `Humanoid:EquipTool()`/`UnequipTools()` lack simulation access. Prediction applies to whole physics assemblies. Client sounds and particles must assume the prediction may be rolled back. — [Server authority model](https://create.roblox.com/docs/projects/server-authority)
- Server Authority techniques: predictive instance creation ("instance stitching") uses deterministic GUIDs so the client can spawn projectiles or objects instantly. "Position smoothing" renders an invisible simulated object with a massless, anchored visual clone that tweens toward it. Animation code should not cache AnimationTracks, because they break on rollback; query `Animator:GetTrackByAnimationId()` instead. Roblox's "Soccer – Server Authority Template" is the reference game. — [Server authority techniques](https://create.roblox.com/docs/projects/server-authority/techniques)
- Rollout timeline: a Studio Beta, then a Client Beta, then a "[Full Release] Ship Fair And Competitive Games with Server Authority" DevForum post. A Roblox newsroom post titled "Creating responsive, cheat-resistant games with Roblox server authority" is dated July 2026. — [Roblox Newsroom (July 2026)](https://about.roblox.com/newsroom/2026/07/creating-responsive-cheat-resistant-games-roblox-server-authority); [DevForum Studio Beta](https://devforum.roblox.com/t/studio-beta-build-fair-responsive-games-with-server-authority/4139157); [DevForum Full Release](https://devforum.roblox.com/t/full-release-ship-fair-and-competitive-games-with-server-authority/4727993); [Tech deep dive](https://devforum.roblox.com/t/server-authority-tech-deep-dive-engineering-insights/4624565). These titles come from search results and were not fetched. One DevForum post is titled "Server Authority Client Beta WAS a damn nightmare. Here's some advice" ([link](https://devforum.roblox.com/t/server-authority-client-beta-was-a-damn-nightmare-heres-some-advice/4712758?page=2)), which suggests migration pain.
- Streaming: StreamingEnabled is on by default for new places. Only Workspace descendants stream. Per-model `ModelStreamingMode` can be Atomic, Persistent or PersistentPerPlayer, and `ModelStreamingBehavior.Improved` is recommended. StreamingTargetRadius should be larger than StreamingMinRadius. Client physics, including Server Authority prediction, "only occurs in streamed areas." The replication focus defaults to the character's PrimaryPart and can be overridden with `Player.ReplicationFocus`. — [Instance streaming](https://create.roblox.com/docs/workspace/streaming)
- Roblox's official "Plant" reference project (a farming microgame: plant, water, harvest, sell) is the closest official template for farming/idle and plot games. It uses a single server entry Script and a single client entry LocalScript, with singleton systems: Network, PlayerDataServer, Market, CollisionGroupManager, FarmManagerServer, PlayerObjectsContainer, TagPlayers, FtueManagerServer and CharacterSpawner. Each player's farm is cloned from a ServerStorage template into a Workspace folder on join, rebuilt from saved data, and removed on leave. `Players.CharacterAutoLoads` is off until data loads. — [Plant reference project](https://create.roblox.com/docs/resources/plant-reference-project) ([GitHub mirror](https://github.com/Roblox/creator-docs/blob/main/content/en-us/resources/plant-reference-project.md))
- Plant's networking order of preference is: (1) replicate via the player-data system (for example `PlayerDataServer.setValue(player,"coins",5)` with the client subscribing to `updated`), (2) attributes, which "replicate atomically with the instance" when set before parenting and are used for plant growth status, (3) CollectionService tags, and (4) direct Network-module messages. The Network module does runtime type validation on all client arguments. — [Plant reference project](https://create.roblox.com/docs/resources/plant-reference-project)
- Plant's client applies WalkSpeed/JumpHeight through multipliers (LocalWalkJumpManager), so multiple systems don't conflict. — [Plant reference project](https://create.roblox.com/docs/resources/plant-reference-project)

**Shooter / FPS / melee**
- In Roblox's official Laser Tag curriculum, the **client** raycasts from `currentCamera.CFrame`, builds BlastData (origin CFrame, ray results, tagged player) and sends it by RemoteEvent. The **server** re-derives the spread directions itself via the shared `getDirectionsForBlast`. It then checks types, angle error against `BLAST_ANGLE_SANITY_CHECK_TOLERANCE_DEGREES`, shooter-to-origin distance and target-to-hit distance against `DISTANCE_SANITY_CHECK_TOLERANCE_STUDS`, and line-of-sight via `isRayPathObstructed`, to catch exploiters who delete walls locally. Typical origin drift while moving at default speed printed as about 1.9–4.8 studs, and the tolerance must be raised if movement speed goes up. Fire rate is enforced with a heat/cooldown attribute (`secondsBetweenBlasts`), checked on both sides. — [Detect hits](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/detect-hits); [Implement blasters](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/implement-blasters) (both read via the GitHub mirror)
- Community consensus (DevForum): "client-side hit detection with server validation" is the most common pattern for competitive Roblox shooters. Valve-style rewind is hard because Roblox's interpolation buffer is undocumented and tick rates are low. One developer saw hitboxes still about 0.5 stud off while jumping, even after compensating. — [FastCast server hit detection thread](https://devforum.roblox.com/t/fastcast-server-hit-detection-not-being-accurate/3184634); [Server-authoritative projectiles with lag compensation](https://devforum.roblox.com/t/server-authoritative-projectiles-with-lag-compensation-multi-threading-and-more/2546164/12); [Server/Client raycast lag compensation](https://devforum.roblox.com/t/serverclient-raycast-lag-compensation/3404150) (snippets only)
- Chickynoid (MIT, `easy-games/chickynoid`, by MrChickenRocket and Brooke, sponsored by easy.gg): it replaces Humanoid characters and trusts only input directions, buttons and (to a limited degree) dt. Each frame the client generates a "command", simulates locally, and sends it. The server simulates the same command and corrects, and the client rolls back and replays unconfirmed commands. It includes rayscan and projectile weapons with server-side hit detection and lag compensation, custom collision (parts, terrain, convex-hull meshes), per-client selective replication, "nearly 2x lower bandwidth than stock roblox", and server bots/NPCs. It detects speed hacks (too much simulated time) and lag hacks (too few commands), and generates fake commands on underrun. Clients go into deliberate lag above 120 fps (configurable). Drawbacks: a fixed-size box character, no physics push/ride, and "a platforming character with a gun and not much else." Shipped example: Anarchy Arena. — [Chickynoid README (GitHub)](https://github.com/easy-games/chickynoid/blob/main/README.md); [DevForum thread](https://devforum.roblox.com/t/chickynoid-server-authoritative-character-replacement/1660558)
- FastCast (projectile sim without physics replication) is no longer maintained by its original author. Community successors include FastCast2 (an "unofficial continuation", adding parallel Luau and types), SimpleCast (lighter, custom physics) and HomingCast. — [FastCast2 docs](https://weenachuangkud.github.io/FastCast2); [SimpleCast DevForum](https://devforum.roblox.com/t/simplecast-an-alternative-to-fastcast/2271321); [Alternatives to fastcast?](https://devforum.roblox.com/t/alternatives-to-fastcast/2630169); [HomingCast](https://devforum.roblox.com/t/homingcast-homing-projectiles/3786022)

**Tower defense**
- Community pattern: the server keeps enemies as data tables (id, path progress, HP, speed) and clients render the models. Enemy position is deterministic along a known path, so clients can compute it from spawn time plus elapsed time (`workspace:GetServerTimeNow()`), moving models on `RunService.PreRender` (formerly RenderStepped). Reported resync intervals range from about 1 s full-table snapshots to about 10 updates per second. — [How to start on client rendering for a TD](https://devforum.roblox.com/t/how-to-start-on-client-rendering-for-a-tower-defense/3008166); [Problem with rendering enemies client-sided](https://devforum.roblox.com/t/problem-with-rendering-enemies-on-client-sided-tower-defense/4525596/4); [Client side rendering confusion](https://devforum.roblox.com/t/client-side-rendering-confusion/2701037); [How would I render enemies on the client](https://devforum.roblox.com/t/how-would-i-render-enemies-on-the-client-for-a-tower-defense-game/1815339) (snippets)
- One developer reports enemy rendering stays smooth up to about 1,000 enemies, while **tower targeting** causes the lag. The suggested fix is a quadtree or octree spatial index instead of an O(towers × enemies) scan. — [How to optimize tower system](https://devforum.roblox.com/t/how-to-optimize-tower-system/2830931/9)
- Another developer moved from fully client-side enemies back to "server-side [simulation] with client-side visualization" because of exploit risk. — [Help on enemy TD path optimization](https://devforum.roblox.com/t/help-on-enemy-td-path-optimization/3315448)

**Horror / AI monsters**
- Common DevForum advice is to call `HumanoidRootPart:SetNetworkOwner(nil)` on NPC monsters. Roblox otherwise hands ownership to the nearest player, which causes stutter and breaks pathfinding and MoveTo mid-chase. Client ownership is only acceptable in single-player, because "if the player owns the zombies, they may be able to move them." Another tip is to switch from PathfindingService to direct raycast/MoveTo chasing when the monster has line of sight, since large rigs can break pathfinding. — [Should the client own AI network ownership?](https://devforum.roblox.com/t/2454116); [NPC logic on client vs server](https://devforum.roblox.com/t/npc-logic-on-client-vs-server/3686069); [Chasing AI freezes/stuttering](https://devforum.roblox.com/t/issue-chasing-ai-freezes-and-stuttering-more-common-with-mutiple-at-once/2273180) (snippets)

**Steal-style / base-plot games ("Steal a Brainrot"-type)**
- Core loop: buy units from a shared conveyor ("red carpet"/belt), or steal them from unlocked rival bases, then place them on base slots. Each slot accumulates cash shown on a "Collect" label, so income doesn't go straight to the wallet. The carrier of a stolen unit is slowed, has items disabled, and the owner is alerted; one hit returns the unit. — [allthings.how guide](https://allthings.how/steal-a-brainrot-roblox-efficient-stealing-events-and-rebirths); [PC Gamer](https://www.pcgamer.com/games/sim/one-of-robloxs-biggest-experiences-right-now-is-a-bizarre-italian-brainrot-character-stealing-simulator-and-lord-help-me-i-now-understand-why-its-so-popular)
- Base lock timers reported: about 60 s re-lock, +10 s per rebirth, +10 s with VIP, and about 30 s auto-lock on join. Guides conflict. One guide claims offline income accrues at about half the online rate (single, unverified source). — [allthings.how](https://allthings.how/steal-a-brainrot-roblox-efficient-stealing-events-and-rebirths); [u7buy mechanics](https://www.u7buy.com/blog/steal-a-brainrot-game-mechanics/); [driffle](https://driffle.com/blog/how-to-steal-in-steal-a-brainrot/)

**Farming/idle ("Grow a Garden"-type)**
- Seed shop restocks about every 5 min, Gear shop about every 5 min, Egg shop about every 30 min (reported for the sequel "Grow a Garden 2"). Stock is reported as **shared globally across servers**, so everyone sees the same shop, which implies a deterministic seed from time or a MemoryStore/MessagingService-backed schedule. An instant restock is sold for 39 Robux. — [allthings.how GaG2 stock](https://allthings.how/grow-a-garden-2-stock-predictor-how-restock-timing-works/); [nerdschalk restock times](https://nerdschalk.com/grow-a-garden-2-shop-restock-times/); DevForum how-to: [How to make stock system like grow a garden?](https://devforum.roblox.com/t/how-to-make-stock-system-like-grow-a-garden/3667791) (title only)

**Dress-up / fashion competition ("Dress to Impress"-type)**
- Round loop: intermission announces a theme (banner and timer), then about 6 min of dressing (18-item cap, 24 with a gamepass), then about a 7 s runway walk per player, rated 1–5 stars by everyone else. The top 3 get the podium, and everyone gets Stars and Cash by placement. Themes can be bought with Robux-priced "Theme Props" during intermission. Server tiers are Freeplay (no timer or voting), Casual, Regular, Pro, Master, VIP and "Style Showdown" (a 10-player elimination mode with immunity idols). Theme voting reportedly toggled on and off several times (added Aug 2024, returned Aug 2025 as a vote every 4 rounds, removed May 2026, per one fan wiki). — [Sportskeeda definitive guide](https://sportskeeda.com/roblox-news/dress-to-impress-a-definitive-guide); [rblxguide themes guide](https://rblxguide.com/games/dress-to-impress/updates/themes-guide); [Beebom Style Showdown](https://beebom.com/dress-to-impress-style-showdown-mode-explained/amp/); [allthings.how](https://allthings.how/?p=317698)

**Survival co-op ("99 Nights in the Forest"-type)**
- Loop: keep a campfire burning, gather resources, survive night cycles toward night 99, rescue 4 missing children. Co-op works best with fixed roles, and classes include Fisherman (added with the 15 Aug 2025 fishing update). **No save**: progress is lost on logout, so runs are session-scoped. Seasonal secret badges are used, for example Halloween 2026. — [Gamezebo: can you beat it alone](https://www.gamezebo.com/walkthroughs/can-you-beat-99-nights-in-the-forest-alone/); [Gamezebo: does it save](https://www.gamezebo.com/walkthroughs/does-99-nights-in-the-forest-save/); [Sportskeeda fishing update](https://www.sportskeeda.com/roblox-news/99-nights-forest-fishing-update-guide)

### Inferences
Per-genre architecture sheets, synthesized from the findings above plus standard Roblox practice. Engine facts are cited above; design choices are mine.

- **Obby/parkour:** Movement stays client-owned under Humanoid physics (Server Authority is optional, and mostly worth it for competitive speedrun or race modes). The server owns `stage` per player and a checkpoint index, validated on touch (see Q2). Stages are static and streamed, with kill bricks and moving platforms often animated client-side for smoothness. Data model: `{stage:int, bestTimes:{[stage]=sec}, skips:int, trails/cosmetics}`.
- **Simulator (incremental/pet):** Server-owned currency, multipliers and pet inventory. Clients render pickups, orbs and pets (pet following is visual-only on the client). Only aggregates replicate: the Plant approach of replicating a player-data table beats per-coin remotes. Pet hatching RNG runs on the server only, and the client plays the egg animation after the server result comes back. Collect actions are rate-limited and distance-checked.
- **Tycoon:** One plot per player, cloned from a ServerStorage template on join and returned to the pool on leave (the Plant FarmManager pattern). Buttons and droppers live on the server. Ore and drop parts are best simulated as a server timer that credits income, with optional client-side visual droppers, instead of thousands of physical parts. Save the list of purchased item IDs and rebuild on join.
- **Round-based (PvP minigames / murder-mystery / BR):** A server state machine (Intermission → Voting → Load map → Play → Results) with time synced through `workspace:GetServerTimeNow()` or attributes on a ReplicatedStorage state object. Maps are cloned from ServerStorage per round. Roles (murderer/sheriff) are assigned on the server and revealed only to the role holder. Don't replicate roles to all clients, or exploiters can read them. BR uses streaming plus a shrinking server-owned zone.
- **Shooter/melee:** Pick one of three tiers. (a) Client hit detection with Laser Tag-style server sanity checks (cheapest, casual). (b) Engine Server Authority (2026 default for competitive games, but Tools are not yet fully supported). (c) Chickynoid (custom, box character). Melee hitboxes: server-side spatial queries (`GetPartBoundsInBox`) at the swing frame, or client-reported hits checked against server position and range.
- **Horror:** Server-owned monster with `SetNetworkOwner(nil)`. The client handles all atmosphere: lighting, local-only jumpscares, spatial Sound. In co-op, door and room generation is seeded on the server and replicated. In story games, per-player cutscenes run on the client.
- **RPG/adventure:** StreamingEnabled with Persistent or Atomic models for quest-critical NPCs and interactables. Quest state lives in server player data. Inventory is server-authoritative, with item instances as IDs plus rolled stats. NPC AI is server-side at low tick (e.g. 5–10 Hz) with client animation interpolation. Enemies should be spawned and despawned near players.
- **Tower defense:** Server tables with deterministic paths. Clients render from `spawnTime + speed × (now − t0)` along a precomputed path-distance curve. Send only spawn/death/status deltas, plus a periodic resync. Spatially index enemies for tower targeting. The server owns placement validation, money and wave scaling.
- **Hangout/roleplay:** Mostly client cosmetics, with server-owned houses, plots and vehicles. Moderation tooling (TextChatService filtering, report hooks) matters more than combat security.
- **Grow-a-garden farming idle:** Plant reference architecture, plus plant growth stored as **timestamps** (plantedAt, growDuration, mutations) so growth continues offline and is computed at load time. A global shop restock is derived from `floor(os.time()/300)` as a seed, so all servers agree without cross-server messaging. Weather and mutation events are server-wide.
- **Steal-style:** Plot pool plus a shared conveyor spawner on the server. Base lock is a server-owned attribute with an expiry timestamp. Carried units are server-attached to the carrier. Income accrues per slot as `rate × elapsed` and is computed lazily on collect.
- **Fishing (Fisch-type):** The cast and reel minigame plays on the client, but the server rolls the catch (location, rod, bait, weather, luck) on cast. It should accept a "reel success" only within a plausible time window, and rate-limit per rod so macros gain little (see Q2).
- **Dress-up:** A round state machine as in round-based games. The outfit is a server-validated list of item IDs (cap enforced on the server). Votes are collected by the server, one per voter per target, with self-votes ignored.
- **Survival co-op:** A session-scoped world state on the server (day/night clock, fire fuel, resource nodes) with no persistence beyond meta-unlocks such as classes and badges. That simplifies DataStore risk.

## Q2. Genre-specific exploits and fixes

### Takeaway
Roblox's official guidance is "defensive design": build mechanics so cheating is impossible or worthless, rather than detecting it after the fact. Concretely, that means sequential server-validated checkpoints, server-computed damage, server-side cooldowns plus inventory-state validation on every transaction, and server-side placement checks.

### Cited Findings
- Official "Defensive design tactics" examples:
  - **Obby** teleport-to-end: design mandatory sequential checkpoints. The server validates that each was activated in order before granting rewards, and flags "faster than humanly possible" completions.
  - **Combat**: the server calculates all damage from server-side weapon stats and validates hits with server raycasts.
  - **Economy** duplication via rapid requests: server-side cooldowns, and validate every transaction against current inventory state.
  - **Shooter** kill farming with bots: reduce or remove points for killing newly spawned players.

  — [Defensive design tactics](https://create.roblox.com/docs/scripting/security/defensive-design) (read via the [GitHub mirror](https://github.com/Roblox/creator-docs/blob/main/content/en-us/scripting/security/defensive-design.md))
- Obby specifics (DevForum): the common exploit is teleporting to a later stage brick, which works if the game never checks earlier stages. Fixes: accept stage N only if the current stage is N−1, add distance-over-time checks, and never let a remote that takes only a stage number or player name advance stages. Skip-stage purchases should be granted via `MarketplaceService.ProcessReceipt` on the server. — [Good anti cheat for an obby](https://devforum.roblox.com/t/good-anti-cheat-for-an-obby/3576031); [+1 Speed Escape Obby anti-cheat](https://devforum.roblox.com/t/how-can-i-properly-make-anti-cheat-for-a-1-speed-escape-obby/4525520) (snippets)
- Tower defense placement: the client can send any position, so the server should accept only a position from a valid (server-repeatable) raycast that hits an instance inside the placement folder or zone. It should also check overlap against existing towers (raycast plus bounds), process placements one at a time so high-ping double placement can't stack towers, and reject tower types the player doesn't own. — [TD preventing exploiters abusing placements](https://devforum.roblox.com/t/tower-defense-game-preventing-exploiters-from-abusing-placements/3801331); [Sanity checks on tower placement](https://devforum.roblox.com/t/how-could-i-implement-sanity-checks-on-a-tower-placement-system/2891740); [Placement validation to prevent overlap](https://devforum.roblox.com/t/tower-placement-validation-to-prevent-overlap/3942949); [Tower placement issue](https://devforum.roblox.com/t/tower-defense-placement-issue/3301401) (snippets)
- Shooter silent-aim and wallhack mitigation in the official sample: the server recomputes the expected spread angles and rejects deviations beyond an angle tolerance. It also checks the shooter is near the claimed origin and the victim is near the claimed hit point, and re-raycasts to confirm no wall blocks the path, which catches local wall deletion. — [Detect hits](https://create.roblox.com/docs/tutorials/curriculums/gameplay-scripting/detect-hits)
- Movement exploits (fly, teleport, noclip, speed) are eliminated or nearly eliminated by server-authoritative controllers (Chickynoid, engine Server Authority). — [Chickynoid README](https://github.com/easy-games/chickynoid/blob/main/README.md); [Server authority model](https://create.roblox.com/docs/projects/server-authority)
- Plant reference: all client→server remote arguments are type-validated at runtime by a central Network module. Soft-currency purchases go through the server Market system. — [Plant reference project](https://create.roblox.com/docs/resources/plant-reference-project)
- Fishing games and macros: Fisch players widely use AutoHotkey-style AFK macros, and there are unverified community claims (Oct 2026) of more bans tied to macro and exploit communities. Sources disagree on whether macros are permitted; the Discord reportedly bans sharing them. — [Roonby Oct 2026](https://roonby.com/2026/10/03/fisch-is-banning-macros-more-now/); [Roonby Mar 2025](https://roonby.com/2025/03/05/fisch-macro-controversy-is-it-bannable-now/amp/) (low-reliability sources)
- Horror and NPC games: giving clients network ownership of monsters lets exploiters move them. — [Should the client own AI network ownership?](https://devforum.roblox.com/t/2454116)

### Inferences
- **Simulator auto-farm:** You can't fully stop it. Make it worthless instead: rate-limit collection on the server per player (e.g. max N collects/s), require proximity checks against the server-side character position, and put most progression into hatching and rebirth gates rather than raw click rate. Many top simulators ship an official auto-farm gamepass, which turns the exploit into monetization (see also Fisch's official auto-fish items in Q3's sources).
- **Tycoon button abuse:** Buttons must check on the server, in order: plot ownership, prerequisite purchased, not already purchased, and enough money. A per-player mutex or debounce stops double-fire duplication. Never trust a client-sent price.
- **Trading (pets/brainrots/plants):** Two-phase confirm with a server-side lock on both inventories. Re-validate ownership at commit, with atomic DataStore `UpdateAsync` or session locking (ProfileStore-style) to prevent dupes when a server crashes mid-trade.
- **Round-based role leaks:** Never put a murderer's or imposter's role in replicated attributes or values visible to all clients.
- **Global shop / restock:** Compute stock on the server from a time seed. The client only displays it. The purchase remote re-checks the current slot's stock.
- **Steal-style:** The server owns the base-lock state and carrier attachment. Stealing requires server proximity to the slot and lock expiry, and drop-on-hit is server-resolved.
- **Dress-up voting:** Server-side one-vote-per-target, and detect alt-account vote rings with simple heuristics (same friends group always 5★). This is speculative design; no source was found.

### Gaps
- No primary-source writeups were found on how specific hit games (Grow a Garden, Steal a Brainrot, TDS, Doors) actually implement anti-cheat.
- No official Roblox data on exploit prevalence by genre. Hyperion (the Roblox client anti-tamper) was not researched here.

## Q3. Progression/economy numbers, session lengths, monetization fits per genre

### Takeaway
Hard genre-specific numbers are scarce in public. The best cross-genre benchmarks come from GameAnalytics' 2025 Roblox report: median D1 10.3%, D7 1.6%, D30 0.5%; top 1% at D1 22.2%, D7 9.1%, D30 4.7%. Roblox's dashboard benchmarks against "similar experiences" by internal genre, with a median D1 around 12.4% and a 90th percentile around 24.1% in its example. Monetization templates per genre are well established: simulators use tiered progression passes plus limited events plus trading; farming/steal games use timed restocks plus instant-restock and luck products; dress-up uses item-cap passes and theme picks.

### Cited Findings
- GameAnalytics 2025 Roblox report: median D1 10.3%, D7 1.6%, D30 0.5%. Top 1%: D1 22.2%, D7 9.1%, D30 4.7%. The common "20% D1 good / 40% excellent" rule is called inflated. The gap in session length between low and top performers widened from about 6x in 2023 (4 vs about 25 min) to nearly 15x by mid-2025 (2 vs 37+ min). - **Monetization fit by genre (synthesis):**

  - Shooter: cosmetics and battle pass. Avoid pay-to-win stats in competitive games.
  - Horror: revives, cosmetics, early chapters.
  - RPG: inventory space, convenience, cosmetics.
  - TD: unit crates, premium units, VIP speed-up (2x/3x game speed).
  - Farming: instant restock, luck and weather boosts, pet eggs.
  - Steal-style: lock-time extensions, special units, server-luck boosts.
  - Dress-up: item-cap passes, theme picks, exclusive clothing.
  - Survival: classes, cosmetics.
- The GameAnalytics finding (top games win on return frequency) supports designs with **timers that reward coming back**: restock clocks, crop growth timestamps, offline income, daily quests. This matches the farming, steal and simulator hits.

## Q4. Live-ops patterns of top 2025–2026 hits

### Takeaway
2025–2026 hits run on a **fixed weekly update slot** (usually Friday or Saturday), preceded by a roughly one-hour **"Admin Abuse"** live event in which developers trigger server-wide weather, spawns and shop manipulation. They also use **global synchronized shop restocks**, **limited-time event items** that feed trading economies, and frequent mode and server-type experiments (e.g. theme voting toggled on and off).

### Cited Findings
- Grow a Garden "Admin Abuse": usually about 1 hour before the weekly content drop. It includes admin-only weather events, shop stock manipulation and unique NPC spawns, and players cannot trigger it. — [Sportskeeda: when admin abuse starts in GaG](https://www.sportskeeda.com/roblox-news/when-admin-abuse-start-grow-garden); [Gamepressure: what is Admin Abuse in GaG](https://www.gamepressure.com/newsroom/what-is-admin-abuse-in-grow-a-garden-gag-we-explain-what-to-expec/z58490); [bo3.gg](https://bo3.gg/games/articles/grow-a-garden-when-does-admin-abuse-start)

### Inferences
- **Architecture implications of live-ops:**
  - Admin abuse needs a server-wide event bus: MessagingService broadcast from an admin panel to all servers, plus a MemoryStore flag so new servers join mid-event.
  - Events should be **data-driven** (event config tables for weather multipliers and spawn tables) so they can be triggered without shipping code.
  - Global restocks are cheapest as deterministic functions of `os.time()` rather than cross-server messages.
  - Weekly updates call for feature flags and version-tagged config, so old servers can be shut down gracefully (soft shutdown) at the update slot.
- Scheduling a fixed weekly slot and an event an hour before it concentrates CCU, which helps discovery. This is consistent with the GameAnalytics finding that return frequency is the big differentiator, but no source directly measures the effect.
- Limited items plus trading create retention but bring dupe and scam risk (PS99 shows this). Trading systems need the atomic, session-locked inventory design from Q2.
